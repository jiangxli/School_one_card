商户校园卡支付接口

商户对接ID（UUID）

校园卡支付渠道

消费由商户系统发起。商户生成本地流水号并选择校园卡支付；一卡通API校验校园卡、完成扣款，在本次HTTP响应中返回一卡通订单号及最终处理状态。

充值独立于日常消费渠道，仅向已建立可信收款关系的机构开放。接口默认关闭，充值权限默认关闭。

新密钥仅显示一次；重置后接口停用，双方更新密钥后重新启用。

提供的API

接口路径（POST）用途
/api/v1/merchant/balance查询卡片钱包余额及是否可消费
/api/v1/merchant/pay提交商户消费，生成一卡通订单并同步返回扣款结果
/api/v1/merchant/query按商户流水号或一卡通订单号查询结果
/api/v1/merchant/recharge独立充值业务，生成一卡通订单并同步返回充值结果
签名及编号规则

商户流水号merchantSerialNo由商户生成，同一业务重试保持不变；一卡通订单号campusOrderNo由一卡通受理交易时生成。数据库内部资金记账编号不作为商户流水号返回。无需先调用申请订单接口。

请求头：X-Merchant-Id、X-Timestamp、X-Nonce、X-Signature
签名：HMAC-SHA256（密钥先Base64解码，结果为小写十六进制）
原文：timestamp + "\n" + nonce + "\n" + path + "\n" + rawBody
时间戳使用Unix秒，误差最多5分钟；每次通讯更换nonce。
交易JSON字段（均为字符串）：merchantId、merchantName、merchantSerialNo、cardNo、amount、occurredAt、location、description
余额查询：merchantId、cardNo
结果查询：merchantId、merchantSerialNo（或campusOrderNo）

网络超时不代表扣款失败。请先按原商户流水号查单，或用原流水号及完全相同参数重试；不可更换流水号盲目重复消费。接口直接返回处理结果，不采用异步推送。

模拟商户系统调用

联调模拟商户端：生成本地流水 → 查校园卡余额 → 提交消费 → 查看API同步返回。消费及充值将实际改变开发库余额。
